Mad Catz M.M.O. 7+ — protocol research

Reverse engineering the M.M.O. 7+ so it can be configured on Linux and in the browser, without the vendor's Windows-only software.
Reading only — the probe below cannot damage your mouse.
It issues HID GET_FEATURE requests and never SET_FEATURE. A read transfer cannot modify stored settings, so it cannot brick or reconfigure anything. It does not touch firmware. The vendor's own Query* functions were verified to use HidD_GetFeature only, with zero write calls.

For M.M.O. 7+ owners

Run the read-only diagnostic Chrome, Edge or Opera required — WebHID does not exist in Firefox
  1. Click the button above and connect the mouse (try USB-C and the 2.4 GHz dongle — they have different product IDs)
  2. Click Read all reports
  3. Click Export JSON (copies a report to your clipboard)

Then share that JSON, plus your OS, browser version, which connection you used, and whether the device appeared in the picker at all. If the picker is empty, that is a useful finding too.

What this is testing

Everything in this project comes from static analysis of the vendor's own Windows drivers. None of it has been checked against real hardware. The probe answers the four questions that block everything else:

Q1What report IDs and sizes does the device actually declare?
Q2Does a response echo the report ID, or is the buffer shifted?
Q3Is byte 1 really a length field?
Q4Do the complement/integrity bytes validate on read?

Q4 matters most: if the device validates that integrity scheme, it likely rejects malformed writes too — which makes any future write support much safer.

Please don't flash firmware

The firmware transfer protocol has not been reverse engineered, and a failed flash has no confirmed recovery path — the vendor's recovery tool is Windows-only and talks to running firmware over HID. Firmware images are a public download if you want to update, but do that on Windows or in a VM for now.
